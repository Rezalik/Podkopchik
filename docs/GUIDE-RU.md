# Инструкция Podkopchik

Инструкция относится к ветке `feature/universal-routing-engine` и состоянию
Native RC на 8 ноября 2026 года. Это исходная копия приложения, не прошивка
роутера и не архив с чужими подключениями.

## Проверенное Устройство

Проверено и работает на **Xiaomi Redmi Router AX6000, stock layout**:
OpenWrt `25.12.6`, ядро `6.12.112`, board
`xiaomi,redmi-router-ax6000-stock`, архитектура `aarch64_cortex-a53`.

На этом устройстве работает Native с реальными AWG 3.1 без запущенного Xray.
Защищённые DNS/HTTPS, три AWG и обычный Direct проверены; пользователь подтвердил
работу YouTube/Instagram и вход в Roblox после возврата выборочной политики.
Контрольные UDP-запросы Roblox получают ответы. Это не проверка всех игровых
серверов и не доказательство физической работоспособности QUIC.

Для других моделей, нестандартной разметки и других ядер такая проверка
не заявляется. Сборка в VM не заменяет проверку аппаратного роутера.
Длительное наблюдение на момент публикации ещё продолжается.

## Перед Установкой

Проверьте устройство, систему и ресурсы:

```sh
ubus call system board
uname -r
df -h /overlay /tmp
free
```

Сверяйте board ID, а не только торговое название. Не обновляйте прошивку
и не устанавливайте kmod по совпадению имени файла. Для AWG требуется точное
соответствие модуля ядру и ABI установленной OpenWrt.

Базовый установщик требует не менее 15 MB свободного flash, рекомендует 25 MB.
Для Native дополнительно учитываются бинарник, рабочие поколения, журнал DNS,
временная распаковка и запас восстановления. Его preflight рассчитывает бюджет;
обходить проверку или удалять пользовательские данные ради установки нельзя.

До изменения работающего роутера сохраните свои настройки и профили приватно
на компьютере. Архив включает ключи и пароли; не прикладывайте его к GitHub Issue.
Не включайте экспериментальную маршрутизацию без доступного SSH и возможности
вернуть прежнюю конфигурацию.

## Выбор Режима

**Legacy** использует Xray для прозрачной обработки трафика. Для VLESS это
обычный путь; в старой схеме обработка AWG тоже могла проходить через Xray.
Экспериментальный Xray FakeDNS по умолчанию выключен.

**Native** выбирает маршрут до транспорта. Для AWG используются ядро Linux,
nftables, DNAT, маркировка и policy routing. Xray нужен только тем маршрутам,
которые действительно используют VLESS. Native DNS использует собственные
настройки и synthetic-пул; переключатель старого Xray FakeDNS к нему не относится.

Установка исходников не переводит домашний LAN в Native автоматически.
На уже работающем Native не запускайте установщик из старой `main`.

## Новая Установка Legacy

Выполняйте на роутере по SSH с правами root:

```sh
curl -fsSL https://raw.githubusercontent.com/Rezalik/Podkopchik/feature/universal-routing-engine/install.sh -o /tmp/podkopchik-install.sh
PODKOPCHIK_INSTALL_BRANCH=feature/universal-routing-engine sh /tmp/podkopchik-install.sh
```

Если curl отсутствует, используйте wget для того же URL:

```sh
wget -O /tmp/podkopchik-install.sh https://raw.githubusercontent.com/Rezalik/Podkopchik/feature/universal-routing-engine/install.sh
PODKOPCHIK_INSTALL_BRANCH=feature/universal-routing-engine sh /tmp/podkopchik-install.sh
```

Установщик проверяет место и конфликты, ставит недостающие зависимости штатным
менеджером, копирует приложение и перевод. OpenWrt 24.10 использует opkg,
OpenWrt 25.12 использует apk; названия и доступность пакетов проверяет адаптер.
Не требуется выполнять общее обновление всех системных пакетов.

Существующая `/etc/config/podkopchik` сохраняется. Переустановка не сбрасывает
ошибочное старое правило автоматически во всех случаях. Подробности о пакетах
и восстановлении после sysupgrade: [миграция OpenWrt](OPENWRT-25.12-MIGRATION.md).

## Подготовка Native На Компьютере

Простой архив исходников GitHub не содержит готового ARM64-компонента.
Сборка выполняется на Mac/Linux, не на OpenWrt. Нужны Git, Node.js, gettext,
обычные инструменты сборки и закреплённый Go `1.26.10`.

```sh
git clone --branch feature/universal-routing-engine --single-branch https://github.com/Rezalik/Podkopchik.git
cd Podkopchik
go version
sh tools/build-native-candidate.sh "$PWD/.build/native-candidate"
node tools/verify-native-candidate.js .build/native-candidate/podkopchik-native-ax6000-candidate.tar.gz
```

Если нужный Go не находится в PATH, передайте его через переменную `GO`.
Скрипт сравнивает две независимые ARM64-сборки, создаёт архив, полный манифест
и файл `.sha256`. Приложение на роутере использует скомпилированный компонент;
Node.js, npm, Python и Go-сборка на роутере не нужны.

Это локальный RC-артефакт, не подписанный пакет OpenWrt. Проверка SHA256
не заменяет доверие к источнику и просмотр изменений.

## Установка Native-Кандидата

До этого шага базовые зависимости должны быть установлены, а нужные AWG 3.1
пакеты и профили должны быть подтверждены для конкретного ядра. Podkopchik
не устанавливает сторонний AWG kmod автоматически.

1. Перенесите проверенный архив и его `.sha256` в отдельный закрытый каталог
   в `/tmp` роутера. Не распаковывайте сразу в `/`.
2. Проверьте `sha256sum -c`, список файлов, владельца root и права.
3. Распакуйте кандидат в этом временном каталоге.
4. Выполните `sh install-native-dns.sh --preflight` из корня распакованного
   кандидата. Сейчас он допускает именно AX6000 stock / OpenWrt 25.12.6 /
   aarch64; не обходите эту проверку для другой модели.
5. Для уже подготовленной системы выполните
   `sh tools/install-native-rc-files.sh "$PWD"`.
   Этот шаг ставит статические файлы и совместимый Native-компонент,
   но не переключает трафик и не изменяет пользовательскую UCI.
6. До Apply выберите и проверьте synthetic-пул, настройте подключения и правила.

Нужно как минимум 64 MiB свободного tmpfs до переноса/распаковки; preflight
требует 48 MiB оставшегося tmpfs и 96 MiB доступной RAM. Для нового бинарника
резервируется его размер плюс 13,5 MiB flash под журнал, состояние и запас.
Это нижняя граница самого компонента, а не универсальный размер полного обновления.

После установки файлов обновите LuCI и проверьте перевод. Если нужен перезапуск
веб-служб, он выполняется отдельно от маршрутизации:

```sh
/etc/init.d/rpcd restart
/etc/init.d/uhttpd restart
```

Не переносите synthetic-пул домашнего Xiaomi вслепую на другой роутер.
Проверяются адреса LAN/WAN/VPN, реальные маршруты, endpoint/Direct-исключения,
AllowedIPs и уже выдававшиеся пулы. Default route сам по себе не означает
пересечение со всеми кандидатами. Нельзя сбрасывать журнал выданных адресов
или повторно выдавать старые fake-IP другому назначению.

## Подключения В LuCI

Откройте **Службы -> Podkopchik**.

**Для VLESS:** вкладка **«Прокси-ссылки»**, вставьте собственный URI.
Проверка доступности изолирована от основного подключения. Ошибка проверки
не делает ссылку заведомо неправильной; сначала выясните причину.

**Для AmneziaWG 3.1:** вкладка **AmneziaWG**, импортируйте действительный
`.conf`, проверьте конфигурацию и подключение. Корректный формат не равен
успешному handshake. Нужны реальная проверка транспорта и HTTPS-ответ.

Назначьте один основной транспорт и, при необходимости, резервные.
Роль «только правила» предназначена для явных назначений и сама по себе
не добавляет подключение в автоматическое резервирование.

Нельзя считать обычный WireGuard, AWG 2.0 и AWG 3.1 взаимозаменяемыми.
Не меняйте вручную ключи и параметры сервера ради обхода проверки формата.

## Правила И Пресеты

1. В **«Пресетах»** выберите сервис и цель, затем добавьте пресет.
2. В **«Доменных группах»** отредактируйте домены и маршрут.
3. В **«IP-правилах»** добавьте необходимые адреса/CIDR.
4. В **«LAN-устройствах»** настройте поведение клиента, если это требуется.
5. В **«Исключениях»** добавьте прямой доступ к панели/VPS:
   например `panel.example.com` или `203.0.113.10`.

Исключение принимает только host/IP/CIDR, без `https://`, пути или порта.
IP/устройство разрешаются целиком: общий CDN-IP не доказывает один домен.

В **«Дополнительно»** для обычной работы выберите **«Выборочная: только
по правилам»**, а ограничение миграции оставьте выключенным. Настройка
`native_unknown_action=protected` не переводит весь трафик в AWG,
пока действует выборочный режим без ограничения миграции.

В Strict или при включённом ограничении миграции неизвестный трафик также
идёт через защищённый транспорт либо блокируется. Это другая политика.
Не включайте её случайно для лечения одного сайта или игры.

## Применение

Нажмите **«Сохранить и применить»**. В Native откройте **«Состояние»**,
сравните сохранённую и активную политику, проверьте интернет с LAN-клиента
без другого VPN и подтвердите Native Apply. Это требуется и после
применения пресета; простое сохранение UCI недостаточно.

Эквивалент по SSH:

```sh
podkopchikctl validate
podkopchikctl apply
podkopchikctl native-status
# После проверки DNS и интернета, используйте pending-токен из вывода Apply:
podkopchikctl native-confirm PENDING_TOKEN
```

Последняя команда относится только к Native. Токен берётся из текущего Apply,
не из примера и не из старого отчёта. Обычный срок подтверждения 300 секунд.

При ошибке валидации рабочая конфигурация сохраняется. Переключение Native
является защищённой транзакцией: управление сохраняется, а защищённый трафик
не должен выходить напрямую во время неполной активации.

В режиме `transactional` неудачный/неподтверждённый Apply использует штатный
механизм восстановления. При первом переходе, когда подтверждённого Native
ещё нет, возможен защищённый режим восстановления вместо прежней схемы.
Не обещается восстановление произвольного старого DNS-кэша.

На проверенном Xiaomi отдельная аварийная служба отключена и удалена
по запросу владельца. Она не нужна для штатного transactional Apply.
Обычная валидация, журнал поколений и fail-closed не отключены.

## Xray FakeDNS В Legacy

Это отдельный экспериментальный путь старого движка, не настройка Native DNS.
Опции `fakedns_enabled` и `fakedns_hijack_dns` изначально выключены.
Историческая проверка MVP, включая приложение X/Twitter, описана в
[критериях приёмки](ACCEPTANCE.md); она не заменяет текущую приёмку Native.

Только при осознанно включённом Xray FakeDNS в Legacy:

```sh
podkopchikctl generate
xray run -test -config /etc/podkopchik/config.generated.json
nft list chain inet podkopchik dns_prerouting
nft list set inet podkopchik reserved4
jsonfilter -q -i /etc/podkopchik/config.generated.json -e '@.routing.rules[@.outboundTag="direct"].ip[*]'
```

Активный FakeDNS-пул, например `198.18.0.0/15`, не должен находиться в
`reserved4` или в списке private/reserved Direct Xray: иначе запрос не попадёт
в нужную обработку. Ответ с fake-IP ожидаем, но не является реальным WAN-адресом.
Эти команды и выводы нельзя переносить на Native, у которого другие таблицы
и собственный классификатор. Блокировка UDP/443 не добавляется.

## Проверка Работы

```sh
podkopchikctl status
podkopchikctl validate-active
podkopchikctl native-status
ip rule show
ip route show default
nft list table inet podkopchik_native
nft list table inet podkopchik_native_gate
```

Последние Native-команды выполняются только при активном Native.
Отсутствие процесса Xray нормально для AWG-only; это не отказ сервиса.

Проверьте защищённый сервис, обычный Direct-сайт, DNS UDP/TCP и реальное
приложение на устройстве. Один HTTPS 200 не доказывает нормальную работу
видео или UDP/QUIC. Таймаут непроверенного UDP echo-сервера также ничего
не доказывает без отвечающего независимого контроля.

Для правил по доменам клиент должен использовать DNS роутера. На время
проверки отключите сторонний VPN на клиенте; учитывайте DoH/DoT и Private Relay.
Это не предложение постоянно ослаблять безопасность клиентского DNS.

## Обновление

Обновление приложения и ядра Xray являются разными операциями.
Автоматического обновления Xray нет.

Для Legacy можно использовать ветку этой копии:

```sh
uci set podkopchik.main.github_branch='feature/universal-routing-engine'
uci commit podkopchik
podkopchikctl update-check
podkopchikctl update-install
```

Это меняет выбранный источник будущих обновлений, поэтому выполняется
осознанно. Пункт канала `main` означает development-канал; конкретную ветку
определяет `github_branch`.

Для Native используйте полный RC `native-rc-*`, собранный на компьютере или
GitHub Actions. Новый обновлятор сам выбирает Native prerelease, даже если в
старом UCI остались `update_channel=main` и `github_branch=main`. Он не меняет
эти настройки и не скачивает Legacy вместо Native. Проверяет SHA256 из GitHub,
архив до распаковки и манифест; затем только размещает файлы без перезапуска
маршрутизации. На «Статус» выполните Apply, проверьте сеть и подтвердите его.

Старый обновлятор на уже работающем Xiaomi автоматически от этого не изменится.
Первый полный пакет устанавливается отдельно после проверки на Mac. Затем
будущие обновления выполняются через LuCI. Порядок и ограничения:
[локальная разработка и выпуск](LOCAL-RELEASE-WORKFLOW.md). Пока подходящий
prerelease не опубликован, новый обновлятор отказывает, а не использует `main`.

Обновление сохраняет UCI и профили, но перед ним всё равно нужен приватный
план восстановления. Архивы на GitHub не должны содержать ваши ключи.

## Восстановление

Не закрывайте SSH при проблеме после Apply. Сначала проверьте статус,
ошибку валидации, выбранную политику, DNS, состояние назначенного транспорта
и текущие маршруты. Не используйте `flush ruleset` и не удаляйте чужие правила.

Пока Native Apply ещё ожидает подтверждения, можно запросить штатный откат:

```sh
podkopchikctl native-abort PENDING_TOKEN
```

В обычном transactional это не отдельный аварийный daemon. После подтверждения
старый токен не является универсальной командой отката любой версии.
Для Legacy у штатного обновления есть `podkopchikctl rollback`, но старый
Legacy-архив нельзя накатывать поверх Native без проверки совместимости.

Если требуется сознательно отключить фильтрацию и разрешить обычный WAN:

```sh
podkopchikctl cleanup
```

Это меняет намерение маршрутизации, а не просто удаляет мусор. Восстанавливайте
код и состояние согласованным комплектом. Не откатывайте watermark/историю
выданных synthetic-IP из старого архива и не удаляйте её вручную.

## Удаление

Из каталога той версии исходников, которая соответствует установленной:

```sh
# При активном Native сначала явно разрешите отключение маршрутизации:
podkopchikctl cleanup
sh uninstall.sh
```

Пользовательские настройки и профили по умолчанию сохраняются.
Полное удаление вместе с настройками и секретами:

```sh
sh uninstall.sh --purge
```

Не выполняйте purge ради устранения обычной ошибки подключения.

## Частые Вопросы

**Почему приложение не изменилось после обновления страницы?**
Проверьте, что установлен нужный payload и русский LMO, затем сделайте
Cmd + Shift + R или откройте приватное окно. Предупреждение HTTPS-сертификата
LuCI решается отдельно; инструкция не требует отключать проверку сертификатов.

**Почему Roblox или другой сервис идёт через AWG?**
Проверьте режим Strict, ограничение миграции, IP-правила и правила устройства.
В обычной выборочной политике трафик вне правил должен идти Direct.
Не добавляйте произвольные широкие исключения, пока не установлена причина.

**Почему обычные сайты могут перестать открываться, хотя у них Direct?**
Маршрут данных и DNS различаются. При отказе всех защищённых DNS-транспортов
новый DNS-ответ может не появиться; неявного DNS провайдера в Native нет.

**Почему AWG UP, а видео тормозит?**
HTTPS health не измеряет всю пропускную способность и не проверяет каждый
сервер приложения. Нужны проверки MTU/MSS, UDP, потерь, ресурса роутера и
самого транспорта. Регулярный перезапуск процесса не является решением утечки.

**Можно ли удалить все каталоги с названием Native?**
Нет. `native-bin`, `native-state`, allocator и записи владения являются
частью работающего движка, а не лишними архивами. Удалять можно только
проверенные неиспользуемые бэкапы и временные файлы.

## Для Разработчиков

На компьютере, не на рабочем роутере:

```sh
sh tools/check-native-local.sh
node tests/i18n_coverage_smoke.js
node tests/lmo_catalog_smoke.js
git diff --check
```

Сценарии с VM в названии запускаются только в предназначенном одноразовом
Linux/OpenWrt-стенде. Не запускайте лабораторные отказные тесты на домашнем LAN.

В публикацию не включаются `.router-backups/`, `.build/`, временные каталоги
тестов, реальные `.conf`, пароли и токены. Примеры UUID и ключей в синтетических
тестах искусственные. Рабочий репозиторий и архивы с конфигурациями разделены.
